# P3-Q-01 — Claim work safely with SELECT FOR UPDATE SKIP LOCKED

## Objective
Let many workers take jobs from one PostgreSQL table so no job is taken twice.

## Problem
With several workers, "read a pending job, then mark it taken" lets two workers read the same job. Correct claiming is the base of every multi-worker design here.

## Prerequisites
`P2-REC-01` (recovery of unfinished work), `P1-PG-03` (row locks and isolation).
Uses: recovery of unfinished work (P2-REC-01); row locks and isolation (P1-PG-03).

## Techniques
Row locks, `FOR UPDATE SKIP LOCKED`, claim-in-one-statement patterns, `claimed_by`/`claimed_at` columns, observing locks via `pg_locks` / `pg_stat_activity`.

## What you need first
`FOR UPDATE` locks selected rows until the transaction ends. `SKIP LOCKED` makes other workers skip rows that are already locked instead of waiting. This gives a queue-like behavior but not a consistent view of the table. A worker that claims a job and then crashes leaves the job claimed; that gap is why leases exist.

## Practical challenge
First write the naive version and show double claims with a test. Then fix it. Run 8 workers (goroutines, then separate processes) over 1,000 jobs. Kill a worker during claim and during processing and describe what happens to the job in each case.

## Deliverable
`claim` component in PRJ-ENGINE, the double-claim reproduction test, and `project/design/claiming.md` with the observed crash behavior.

## Acceptance criteria
1. Naive version double-claims in a repeatable test.
2. Fixed version: in the no-failure run, every job is claimed by exactly one worker (assert claim counts). This says nothing about what happens after failures; later unlocks define that.
3. Killing a worker mid-claim (before commit) leaves the job claimable.
4. Killing a worker after commit leaves the job stuck, and the document says so plainly.
5. Document names the version of PostgreSQL tested.

## Verification
Evaluator runs the test suite and the kill scenarios. Oral: "Why is a job stuck after commit, and what is the smallest mechanism that fixes it?" (leads into the next unlock).
