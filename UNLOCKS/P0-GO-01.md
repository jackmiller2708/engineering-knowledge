# P0-GO-01 — Set up Go and ship a tested command-line tool

## Objective
Have a working Go toolchain and a first project area (PRJ-LABS) in your workspace containing a small, tested tool. Describe your workspace to the evaluator (no machine paths in this repository).

## Problem
Every later unlock needs a working Go setup and a place where results live. A hex-dump tool is also a real inspection tool for the binary formats built in `P0-BIT-*`.

## Prerequisites
None. Needs Git and Go installed (`ENVIRONMENT.md`).

## Techniques
`go mod init`, packages, `go run/build/test/vet`, `testing` with table-driven tests, reading files with `io.Reader`, `os.Args` / `flag`.

## What you need first
A Go module is a folder with `go.mod`. A package is a folder of `.go` files. Tests are functions named `TestXxx` in `_test.go` files.

## Practical challenge
In PRJ-LABS create a command `xd` that prints a file (or standard input) as a hex dump: byte offset, 16 bytes in hex, then printable ASCII. Put the dump logic in a package separate from `main`, so it can be tested without files.

## Deliverable
The PRJ-LABS project with `go.mod`, the `xd` command, package tests, and a README with run instructions. An evidence bundle (`project/README.md`). Record learner OS and Go version in the evidence.

## Acceptance criteria
1. `go build ./...`, `go vet ./...`, `go test ./...` all pass from a clean copy of the project (the evidence bundle), not only in your working directory.
2. Output for a known 40-byte input matches an expected string in a test.
3. Empty input, input shorter than 16 bytes, and a final partial line are tested.
4. Works on standard input when no file is given.

## Verification
Evaluator runs the three commands from the evidence bundle, runs `xd` on two files, and asks the learner to explain what `go.mod` does and why logic lives outside `main`.

## Mastery target
L3 (apply).
